# 실제 API 연결 검증

## 실행 방법

저장소 루트 `.env`에 공통 필수 설정과 `OPENAI_API_KEY`, `GROQ_API_KEY`를 입력합니다. 키는 커밋하지 않습니다. `ai-module`에서 실행합니다.

```bash
uv sync --locked
uv run --locked python scripts/smoke_embedding.py --run-live
uv run --locked python scripts/smoke_llms.py --run-live
```

`--run-live`가 없으면 도움말만 출력하며 설정 로딩·모델 호출을 하지 않습니다. 두 스크립트는 일반 단위 테스트에 포함되지 않습니다. 실제 실행은 합성 텍스트를 외부 API에 전송하며 계정의 사용량을 소모합니다.

결과는 기본적으로 Git 제외 경로 `ai-module/data/smoke-results/`에 저장합니다. `--output <경로>`로 변경할 수 있습니다. 재실행 결과는 기존 성공 기록과 구분해 검토한 뒤 공유합니다.

## 호출 범위

| 스크립트 | 대상과 설정 | 확인 내용 |
|---|---|---|
| `scripts/smoke_embedding.py` | 설정 로더의 `text-embedding-3-small`, 합성 영문 문장 1개, 재시도 0회 | API 접근, 벡터 1개·1536차원·유한값·비영벡터, 사용 토큰 |
| `scripts/smoke_llms.py` | Groq `openai/gpt-oss-120b` (`low`), OpenAI `gpt-6-luna` (`none`), 각각 1회 | 스트리밍 답변·정상 종료, 합성 자료의 마감시간·출처 표시, 첫 답변 시간·사용 토큰 |

LLM 테스트 대상은 비교 재현을 위해 스크립트에 명시합니다. 서비스의 `LLM_PROVIDER`·`LLM_MODEL`이나 `.env`는 변경하지 않습니다. 호출당 출력 상한은 512토큰(추론 포함), SDK 재시도 0회, SDK 타임아웃 30초, LLM 호출 전체 제한 55초입니다. 임베딩 스크립트는 앱의 공통 생성 함수를 사용하고, LLM 스크립트는 OpenAI 호환 SDK로 공급자 API를 직접 호출합니다. 아직 앱의 LLM 파이프라인을 검증하는 것은 아닙니다.

키·인증 헤더·오류 응답 원문·벡터 원문·추론 본문은 저장하지 않습니다. LLM 결과에는 합성 질문의 최종 답변만 포함합니다. LLM 스크립트의 종료 코드는 답변 정상 종료와 정답 문자열·출처 확인을 모두 반영합니다. JSON의 `success`는 스트림 정상 완료 여부이고 정답 확인은 별도 필드입니다. 문자열 확인은 의미 기반 품질 평가를 대체하지 않습니다.

- 원본 기록: [임베딩](2026-11-07/live-embedding-verification.json), [LLM](2026-11-07/live-llm-verification.json)
- 각각 요청 1회·재시도 없음. 교안이나 사용자 자료는 전송하지 않았습니다.
- 기록은 스크립트의 공유용 정리 이전 실행에서 얻은 결과를 그대로 복사했습니다. 이번 공유용 정리에서는 CLI, 출력 경로, LLM 설정 전달 및 종료 코드 처리를 보완했고 API를 재호출하지 않았습니다.

- 시간은 클라이언트 생성 등 로컬 처리 시간을 포함하는 단일 관측값입니다. 추론 설정도 달라 모델 성능 순위·평균·p95로 해석할 수 없습니다.
- 해당 시점의 키·모델 접근 및 간단한 답변 수신만 확인했습니다. 계정 잔여 한도, PDF 적재·검색 품질, Backend SSE 중계, 운영 환경은 별도 검증 대상입니다.
