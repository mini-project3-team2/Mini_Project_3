## 5. 진행 규칙

- 작업은 GitHub Issue로 담당자 · 기한을 남기고, 커밋 · PR에 `(#번호)`를 붙인다
- `develop`에서 브랜치 → `develop`으로 PR → 리뷰 1명 승인 → **Create a merge commit** (README 6장)
- PR은 하루 1회 이상 작게 올린다
- 담당자가 반나절 이상 연락이 안 되거나 기한을 넘기면 **백업이 이어받는다**
- API 키 · 비밀번호는 단톡방 공지로만 전달하고 커밋 · 캡처 · 발표 자료에 넣지 않는다

## 6. 시간이 부족할 때 빼는 순서

1. 가산 과제 (GKE, Actions → EC2 자동 배포, HttpOnly 쿠키 + HTTPS, MD 형식)
2. 평가 질문셋 · LangSmith
3. 질문 기록 화면의 피드백 변경 (표시만 유지)
4. 내 자료 화면의 드래그 앤 드롭 (파일 선택 버튼만 유지)

> 빼지 않는 것: 로그인 · 업로드 · 질문 스트리밍 · 기록 목록, 소유자 검증, 취약점 3건 근거, EC2 배포
