# API 설계서

> 버전 v0.2 (초안) · 작성 윤수연 · 2026-11-06 팀 검토 후 확정
> 서비스: AskNote (수업 자료 기반 AI 학습 도우미)

## 1. 기본 정보

- **Base URL**
  - 로컬 개발: `http://localhost:8080/api`
  - 배포: `http://<EC2 주소>/api` (Nginx가 `/api`를 Backend로 프록시)
- **인증 방식**: JWT — `Authorization: Bearer <accessToken>`
  - Access Token 15분, Refresh Token 1일 (DB에는 SHA-256 해시로 저장, 재발급 시 회전)
  - Refresh Token은 요청 body로 주고받는다 (쿠키 미사용 → CSRF 비활성 사유)
  - 화면 저장 위치: Access Token은 메모리(Zustand), Refresh Token은 **sessionStorage** (탭을 닫으면 삭제 — 공용 PC 고려)
- **공통 규칙**
  - JSON 필드는 camelCase, 날짜는 ISO-8601 (`2026-11-09T14:30:00`)
  - 페이지 번호는 0부터, 기본 `size=10` (질문 기록 목록만 페이징)
  - 남의 리소스 접근은 **403**, 없는 리소스는 **404**
  - 변경 · 삭제는 GET으로 하지 않는다

## 2. 공통 응답 형식

**성공**
```json
{
  "success": true,
  "data": {},
  "message": ""
}
```

**실패** (500 응답에도 스택 트레이스 · 내부 오류 상세를 넣지 않음)
```json
{
  "success": false,
  "data": null,
  "message": "파일 크기는 10MB 이하여야 합니다",
  "code": "FILE_TOO_LARGE"
}
```

**페이지 응답의 `data`**
```json
{
  "content": [],
  "page": 0,
  "size": 10,
  "totalElements": 23,
  "totalPages": 3
}
```

## 3. 인증 API

| 메서드 | 경로 | 인증 | 설명 |
|--------|------|:--:|------|
| POST | `/auth/signup` | X | 회원가입 |
| POST | `/auth/login` | X | 로그인 |
| POST | `/auth/refresh` | X | 토큰 재발급 (회전) |
| POST | `/auth/logout` | O | 로그아웃 (Refresh 폐기) |

### 3.1 회원가입
- **POST** `/auth/signup`
```json
{
  "email": "student@example.com",
  "password": "Passw0rd!"
}
```
- 검증: 이메일 형식, 비밀번호 8\~20자 · 영문 · 숫자 · 특수문자 포함
- 비밀번호 확인 입력은 화면에서만 비교하고 서버로 보내지 않는다
- **201** → `data`
```json
{ "uuid": "8f14e45f-...", "email": "student@example.com" }
```
- 오류: 400 `INVALID_INPUT`, 409 `DUPLICATE_EMAIL`

### 3.2 로그인
- **POST** `/auth/login`
```json
{
  "email": "student@example.com",
  "password": "Passw0rd!"
}
```
- **200** → `data`
```json
{
  "accessToken": "eyJ...",
  "refreshToken": "c2Vj...",
  "expiresIn": 900,
  "member": { "uuid": "8f14e45f-...", "email": "student@example.com" }
}
```
- 오류
  - 401 `INVALID_CREDENTIALS` — "이메일 또는 비밀번호가 올바르지 않습니다" (이메일 존재 여부를 구분하지 않음)
  - 423 `ACCOUNT_LOCKED` — 5회 연속 실패 시 15분 잠금, `data.lockedUntil` 포함
- 로그인 성공 · 실패는 감사 로그에 기록 (이메일 마스킹)

### 3.3 토큰 재발급
- **POST** `/auth/refresh`
```json
{ "refreshToken": "c2Vj..." }
```
- **200** → 새 `accessToken` · `refreshToken` (기존 Refresh는 삭제)
- 오류: 401 `INVALID_REFRESH_TOKEN` (없음 · 만료 · 위조)

### 3.4 로그아웃
- **POST** `/auth/logout`
```json
{ "refreshToken": "c2Vj..." }
```
- **204** (본문 없음)

## 4. 자료 API

| 메서드 | 경로 | 인증 | 설명 |
|--------|------|:--:|------|
| POST | `/documents` | O | 자료 업로드 (적재 완료 후 응답) |
| GET | `/documents` | O | 내 자료 목록 |
| DELETE | `/documents/{id}` | O | 내 자료 삭제 |

### 4.1 업로드
- **POST** `/documents`
- **Content-Type**: multipart/form-data — 필드 `file`
- 검증 (서버가 기준, 화면 검증은 보조)
  - **PDF만 허용**: 확장자 `.pdf` + 파일 앞부분이 `%PDF-`로 시작하는지 확인 — 확장자만 바꾼 파일은 거부
  - 크기 10MB 이하, 빈 파일 거부
- 업로드 크기 제한 및 오류 응답 (배포 시 아래 계층을 함께 설정)
  - **nginx**: 업로드 경로 `/api/documents`에 `client_max_body_size 12m;` 적용. 기본값 `1m`으로 정상 PDF가 먼저 차단되지 않도록 Spring의 전체 요청 제한보다 여유 있게 설정한다.
  - **Spring multipart**: `spring.servlet.multipart.max-file-size=10MB`, `spring.servlet.multipart.max-request-size=11MB` 적용. 파일은 10MB로 제한하고, 전체 요청에는 multipart 헤더·경계 등 부가 데이터 공간을 둔다.
  - **Tomcat**: `server.tomcat.max-swallow-size=12MB` 적용. 제한을 넘은 요청을 거부할 때 Tomcat이 남은 본문을 기본 2MB까지만 읽고 연결을 끊어, 11~12MB 요청에서 413 JSON 대신 연결 끊김 · 502가 날 수 있으므로 nginx 제한과 같게 맞춘다.
  - **413 JSON 응답**: Spring의 `MaxUploadSizeExceededException`은 공통 예외 처리에서 HTTP 413과 아래 JSON으로 변환한다. nginx가 자체 제한을 초과한 요청을 먼저 차단하면 Spring에 도달하지 않으므로, nginx에도 `error_page 413` 처리를 설정해 HTML 대신 동일한 JSON과 `Content-Type: application/json`을 반환한다.
```json
{
  "success": false,
  "data": null,
  "message": "파일 크기는 10MB 이하여야 합니다",
  "code": "FILE_TOO_LARGE"
}
```
- 처리: DB 저장(`status = INDEXING`) → AI 적재 요청(파일 내용 전달) → 성공하면 `READY`로 변경 → **적재가 끝나면 응답** (화면은 그동안 로딩 표시)
  - AI 적재 실패 · 타임아웃 시: AI 청크 삭제 요청 → DB 행 삭제 → 오류 응답
  - 원본 PDF는 서버에 저장하지 않는다 (적재 후 임시 파일 자동 삭제)
- 업로드 타임아웃 (안쪽 → 바깥쪽으로 갈수록 길게 — 바깥 계층이 먼저 끊으면 화면은 실패로 보는데 서버는 적재를 계속해, 결과를 화면이 받지 못함)

  | 계층 | 값 | 설명 |
  |------|----|------|
  | Backend → AI 적재 요청 | 120초 | 6.1과 같음. 초과 시 6.2 청크 삭제(별도 10초) → DB 행 삭제 → 503 `AI_UNAVAILABLE` |
  | nginx `/api/documents` | `proxy_read_timeout 150s;` | 기본 60초면 적재 중에 nginx가 먼저 504(HTML)로 끊음 → Backend 최대 처리 시간(120 + 10초)보다 길게 |
  | Frontend 업로드 요청 | 180초 | 공통 HTTP 클라이언트 기본 타임아웃(60초)과 별도로 **업로드 요청에만** 지정, 그동안 로딩 표시 |

- **201** → `data`
```json
{ "id": 12, "originalFilename": "Day5_Spring_Security.pdf", "fileSize": 2483112, "status": "READY", "createdAt": "2026-11-09T10:12:00" }
```
- 오류: 400 `INVALID_FILE_TYPE` · `EMPTY_FILE`, 413 `FILE_TOO_LARGE`, 422 `TEXT_EXTRACTION_FAILED` (글자를 읽을 수 없는 PDF), 503 `AI_UNAVAILABLE` (AI 오류 · 적재 120초 초과)

### 4.2 목록 조회
- **GET** `/documents` (최신순, 페이징 없음)
- **200** → `data` (배열)
```json
[
  { "id": 12, "originalFilename": "Day5_Spring_Security.pdf", "fileSize": 2483112, "status": "READY", "createdAt": "2026-11-09T10:12:00" }
]
```
- `status`: `READY`(답변에 사용) / `INDEXING`(적재 중 — 화면에 "적재 중" 표시, 삭제 가능)

### 4.3 삭제
- **DELETE** `/documents/{id}`
- 처리 순서: AI 청크 삭제 → DB 행 삭제
- **204**
- 오류: 403 `FORBIDDEN` (남의 자료), 404 `DOCUMENT_NOT_FOUND`

## 5. AI 채팅 API

| 메서드 | 경로 | 인증 | 설명 |
|--------|------|:--:|------|
| POST | `/chats/stream` | O | 질문 → 답변 스트리밍 (SSE) |
| GET | `/chats` | O | 내 질문 기록 목록 (페이징) |
| PATCH | `/chats/{id}/feedback` | O | 답변 피드백 등록 · 변경 |

### 5.1 질문 (스트리밍)
- **POST** `/chats/stream`
- **요청 헤더**: `Authorization: Bearer ...`, `Accept: text/event-stream`
- **요청**
```json
{ "question": "JWT Refresh Token 회전은 왜 하는 거야?" }
```
- 검증: 1\~1000자, `READY` 상태 자료가 1개 이상
- 화면은 `EventSource` 대신 **`fetch` + 스트림 읽기**로 받는다 (`EventSource`는 POST · Authorization 헤더를 못 씀)
- 스트리밍 전달 설정 (배포 시 nginx · Backend를 함께 설정)
  - **nginx**: `/api/chats/stream` 경로에 `proxy_buffering off;` · `gzip off;` 적용. 기본 설정은 응답을 모았다가 보내서 답변이 실시간으로 나오지 않고 끝난 뒤 한 번에 표시된다. `proxy_http_version 1.1;` · `proxy_set_header Connection "";`로 연결을 유지하고, `proxy_read_timeout`은 Backend 스트리밍 타임아웃(60초)보다 길게(120초) 두어 타임아웃 시 nginx가 아닌 Backend가 `error` 이벤트로 응답하게 한다.
  - **Backend**: 응답 헤더 `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no` (nginx 버퍼링을 응답 단위로 한 번 더 끔)

**SSE 이벤트 순서**

| 순서 | event | data | 설명 |
|:--:|------|------|------|
| 1 | `sources` | `[{"documentId": 12, "documentName": "Day5_Spring_Security.pdf", "page": 14}]` | 근거 출처 (`page`는 1부터) |
| 2 | `token` (반복) | `{"text": "Refresh Token을 "}` | 답변 조각 |
| 3 | `done` | `{"chatId": 31}` | 완료 — 이때 질문 · 답변 · 출처를 기록에 저장 |
| - | `error` | `{"message": "지금은 답변할 수 없습니다. 잠시 후 다시 시도해 주세요"}` | AI 오류 · 타임아웃(60초), 기록 저장 안 함 |

```
event: sources
data: [{"documentId":12,"documentName":"Day5_Spring_Security.pdf","page":14}]

event: token
data: {"text":"Refresh Token을 "}

event: token
data: {"text":"회전하는 이유는..."}

event: done
data: {"chatId":31}
```

- `page`는 PDF 페이지 번호로 **1부터** 시작한다 (`PyPDFLoader`는 0부터 주므로 AI Module이 적재할 때 +1해서 저장)
- 자료에 없는 내용을 물으면 프롬프트 지시에 따라 "올린 자료에서 관련 내용을 찾지 못했습니다"라고 답한다
- 스트림 시작 전 오류는 일반 JSON 응답: 400 `INVALID_INPUT` · `NO_DOCUMENT`, 401

### 5.2 기록 목록
- **GET** `/chats?page=0&size=10` (최신순)
- 상세 화면 없이 **목록에서 질문 · 답변 · 출처를 바로 보여준다**
- **200** → 페이지 응답, `content` 항목
```json
{
  "id": 31,
  "question": "JWT Refresh Token 회전은 왜 하는 거야?",
  "answer": "Refresh Token을 회전하는 이유는...",
  "sources": [{ "documentId": 12, "documentName": "Day5_Spring_Security.pdf", "page": 14 }],
  "feedback": "HELPFUL",
  "createdAt": "2026-11-09T15:02:00"
}
```
- `feedback`: `HELPFUL` / `NOT_HELPFUL` / `null`(미선택)

### 5.3 답변 피드백
- **PATCH** `/chats/{id}/feedback`
- 채팅 화면에서는 `done` 이벤트의 `chatId`로, 기록 목록에서는 각 항목의 `id`로 호출
- **요청**
```json
{ "feedback": "HELPFUL" }
```
- 검증: `HELPFUL` · `NOT_HELPFUL` 중 하나 (`@NotNull` + enum)
- 이미 있는 기록의 값 하나를 바꾸는 부분 수정이라 PUT이 아닌 **PATCH** 사용, 같은 값을 다시 보내도 결과가 같음
- **200** → `data`
```json
{ "id": 31, "feedback": "HELPFUL" }
```
- 오류: 400 `INVALID_INPUT`, 403 `FORBIDDEN` (남의 기록), 404 `CHAT_NOT_FOUND`

## 6. 내부 API (Backend → AI Module)

> 외부 비공개 (Compose 내부 네트워크 `http://ai-service:8000` = 환경 변수 `AI_SERVICE_URL`, 포트 미게시)
> 모든 요청에 `X-Internal-Token: <환경 변수 AI_INTERNAL_TOKEN>` — 없거나 틀리면 401
> `ownerUuid`는 Backend가 **JWT에서 꺼낸 값**으로만 채운다

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/internal/documents` | 자료 적재 (로드 → 분할 → 임베딩 → Chroma 저장) |
| DELETE | `/internal/documents/{documentId}?ownerUuid=` | 문서 청크 삭제 |
| POST | `/internal/query/stream` | 소유자 필터 검색 → 답변 생성 스트리밍 |
| GET | `/health` | 헬스체크 (인증 X, Docker HEALTHCHECK용) |

### 6.1 자료 적재
- **POST** `/internal/documents` — multipart/form-data
  - `file`, `documentId`, `ownerUuid`, `documentName`
- **200**
```json
{ "documentId": 12, "chunkCount": 57 }
```
- **422** `{"error": "TEXT_EXTRACTION_FAILED"}` (글자를 읽을 수 없는 PDF)
- 적재 중 예외가 나면 AI Module이 해당 `documentId`의 청크를 지우고 오류로 응답한다
- Backend는 응답을 기다린다 (타임아웃 120초, 타임아웃 시 6.2 청크 삭제를 호출해 정리)

### 6.2 청크 삭제
- **DELETE** `/internal/documents/12?ownerUuid=8f14e45f-...` → **204** (청크가 없어도 204)

### 6.3 질의 스트리밍
- **POST** `/internal/query/stream`
```json
{ "question": "JWT Refresh Token 회전은 왜 하는 거야?", "ownerUuid": "8f14e45f-...", "documentIds": [12, 15] }
```
- `documentIds`: Backend가 DB에서 조회한 해당 회원의 **`READY` 문서 id 목록**
- AI는 `owner_uuid`와 `document_id $in documentIds` 두 조건으로만 검색한다 → Chroma에 남은 적재 실패 청크 · 적재 중 청크는 답변에 쓰이지 않음
- 응답 SSE: `sources` → `token`(반복) → `done` / `error`

| event | data | Backend 처리 |
|------|------|------|
| `sources` | `[{"documentId": 12, "documentName": "...", "page": 14}]` (5.1과 같음, `page`는 1부터) | 그대로 화면에 중계 |
| `token` | `{"text": "..."}` (5.1과 같음) | 그대로 중계 + 답변을 모아 둠 |
| `done` | `{}` | 기록 저장 후 `{"chatId": 31}`로 바꿔 화면에 전송 |
| `error` | `{"code": "LLM_ERROR"}` — 원인 코드만 (`LLM_ERROR` · `EMBEDDING_ERROR` · `SEARCH_ERROR`) | 코드는 서버 로그에만 남기고, 화면에는 5.1의 고정 문구 `{"message": "지금은 답변할 수 없습니다. 잠시 후 다시 시도해 주세요"}`로 바꿔 전송 (AI 내부 오류 내용 미노출) |

- Backend는 이벤트를 화면으로 그대로 중계하고, `token`을 모아 `done` 때 기록에 저장한 뒤 `done`에 `chatId`를 붙인다

## 8. HTTP 상태 코드

| 코드 | 설명 |
|------|------|
| 200 | 성공 (조회, 피드백 수정) |
| 201 | 생성 (회원가입, 자료 업로드) |
| 204 | 성공, 본문 없음 (삭제 · 로그아웃) |
| 400 | 잘못된 요청 (입력 검증 실패, PDF가 아닌 파일) |
| 401 | 인증 실패 (토큰 없음 · 만료 · 위조, 로그인 실패) |
| 403 | 권한 없음 (남의 자료 · 기록, ADMIN 전용) |
| 404 | 없음 |
| 409 | 충돌 (이메일 중복) |
| 413 | 파일 크기 초과 |
| 422 | 처리 불가 (글자를 읽을 수 없는 PDF) |
| 423 | 계정 잠금 (로그인 실패 초과) |
| 500 | 서버 오류 (상세 미노출) |
| 503 | AI Module 응답 없음 |

## 9. 확정 값
