# 컨테이너화 및 배포 가이드

> ⚠️ **5.1 AWS EC2 는 초안**입니다 — 11/9 첫 배포를 하면서 실제 값 · 결과로 채웁니다. `<배포 후 기입>` 표시는 배포해야 알 수 있는 값입니다.

## 1. 컨테이너 구성

| 서비스 | 내용 | 이미지 (운영) | 컨테이너 포트 | 외부 공개 |
|--------|------|----------------|---------------|-----------|
| `frontend` | React 빌드 결과 + Nginx (`/api/**` 를 backend 로 프록시) | `<DOCKERHUB_USERNAME>/asknote-frontend` | 8080 (비root nginx) | ✅ 80 → 8080 |
| `backend` | Spring Boot (JWT 인증, 업로드, SSE 중계, Flyway) | `<DOCKERHUB_USERNAME>/asknote-backend` | 8080 | ❌ |
| `ai-service` | FastAPI + LangChain RAG + Chroma(PersistentClient) | `<DOCKERHUB_USERNAME>/asknote-ai` | 8000 | ❌ |
| `database` | MariaDB 10.11 | `mariadb:10.11.19@sha256:…` | 3306 | ❌ |

- 이미지 3종(frontend · backend · ai)은 GitHub Actions 가 main 병합 시 빌드해 Docker Hub 에 Push 하고, EC2 는 **빌드 없이 pull 만** 합니다.
- 볼륨: `db-data`(MariaDB), `chroma-data`(Chroma). 운영 Chroma 는 비어 있는 상태로 시작하고 자료를 다시 업로드해 적재합니다 (개발 데이터 복사 금지).

## 2. Docker 설정

세 Dockerfile 공통: **멀티스테이지**(빌드 도구는 실행 이미지에 미포함) · **비root 실행** · **HEALTHCHECK** · **베이스 이미지 패치 버전 태그 + digest 고정** (보안점검서 I-2 · I-4)

### 2.1 Frontend (`frontend/Dockerfile`)
| 단계 | 베이스 이미지 | 내용 |
|------|---------------|------|
| 빌드 | `node:24.22.2-alpine3.24@sha256:…` | `npm ci` → `npm run build` (`VITE_API_URL=/api` build-arg, 비밀값 금지) |
| 실행 | `nginxinc/nginx-unprivileged:1.31.7-alpine3.24@sha256:…` | uid 101, 포트 8080, `nginx.conf` · `dist/` 만 복사 |

- `nginx.conf`: SPA 라우팅 fallback, 보안 헤더(CSP 등), `/actuator` 404, 숨김 파일 차단, 업로드 `client_max_body_size 12m` · `proxy_read_timeout 150s`, 스트리밍 `proxy_buffering off` · `proxy_read_timeout 120s`, 413 JSON 응답
- 요청 횟수 제한(`limit_req`, 클라이언트 IP 별): `/api/auth/**` 20회/분 · `/api/chats/stream` 10회/분 · `/api/documents` **POST 만** 6회/분, 초과 시 429 JSON `TOO_MANY_REQUESTS` (보안점검서 6.8)
- HEALTHCHECK: `wget -q --spider http://127.0.0.1:8080/`

### 2.2 Backend (`backend/Dockerfile`)
| 단계 | 베이스 이미지 | 내용 |
|------|---------------|------|
| 빌드 | `eclipse-temurin:17.0.21_9-jdk-resolute@sha256:…` | Maven Wrapper `dependency:go-offline`(캐시) → `package -DskipTests` |
| 실행 | `eclipse-temurin:17.0.21_9-jre-resolute@sha256:…` | 전용 사용자 `app`, jar 는 root 소유(읽기 전용), `-XX:MaxRAMPercentage=75` |

- HEALTHCHECK: `curl -fsS http://127.0.0.1:8080/actuator/health`

### 2.3 AI Module (`ai-module/Dockerfile`)
| 단계 | 베이스 이미지 | 내용 |
|------|---------------|------|
| 빌드 | `python:3.12.16-slim-trixie@sha256:…` + `ghcr.io/astral-sh/uv:0.12.23@sha256:…` | `uv sync --locked --no-dev` (uv.lock 과 다르면 빌드 실패) |
| 실행 | `python:3.12.16-slim-trixie@sha256:…` | `.venv` · `src` 만 복사, 전용 사용자 `app`, Chroma 볼륨 위치(`/data/chroma`)만 `app` 소유로 지정 |

- HEALTHCHECK: Python 표준 라이브러리로 `http://127.0.0.1:8000/health` 확인 (slim 에 curl 없음)
- `.dockerignore`: `.env` · `.env.*` · `*.pem` · `*.key`, `.venv`, 로컬 Chroma 데이터(`chroma_db`), `uploads`, `.git` 등 제외 → 비밀값 · 개발 데이터가 이미지에 들어가지 않음

### 2.4 베이스 이미지 갱신 절차 (보안점검서 6.7)
1. 새 태그 확인 → 2. Dockerfile · Compose 의 **태그 · digest 함께 변경** → 3. `docker compose up -d --build` 로 `healthy` 확인 → 4. Trivy 재검사(`docs/security/trivy-image-*.txt`) → 5. README · 산출물 버전 표기 갱신

## 3. Docker Compose

| 항목 | 로컬 `docker-compose.yml` | 운영 `docker-compose.prod.yml` |
|------|---------------------------|--------------------------------|
| 이미지 | `build:` (소스에서 빌드) | Docker Hub 이미지 `${DOCKERHUB_USERNAME}/asknote-*:${IMAGE_TAG:-latest}` |
| 포트 게시 | 디버깅용, **`127.0.0.1` 에만** (80 · 8080 · 8000 · 3306) | **frontend `80:8080` 만** |
| 네트워크 | `app-net` 1개 | `edge-net`(frontend · backend) / `ai-net`(backend · ai-service) / `db-net`(backend · database, **`internal: true`**) |
| 메모리 상한 | 없음 | `mem_limit` database 512m · ai-service 1g · backend 1g · frontend 128m (합계 약 2.6GB, 잠정값) |
| 로그 | 기본 | json-file `10m × 3` 개로 제한 |
| 컨테이너 권한 | 운영과 동일 | `no-new-privileges` 4종, frontend · backend · ai-service `cap_drop: ALL` (database 는 공식 이미지 기동에 chown · 사용자 전환 권한이 필요해 제외, 보안점검서 6.8) |

- 기동 순서: `database` · `ai-service` 동시 기동 → 둘 다 healthy 후 `backend`(Flyway 실행) → backend healthy 후 `frontend` — `depends_on: condition: service_healthy`
- 환경 변수는 **서비스별 `environment:` 에 그 서비스가 쓰는 값만** 전달 (`env_file` 미사용, `docs/Compose_환경변수_작성가이드.md`)
  - backend: DB 계정 · JWT · CORS · Actuator · 관리자 계정 · AI 주소 · 내부 토큰 (LLM 키 없음)
  - ai-service: 내부 토큰 · LLM · 임베딩 설정 · API 키 (DB · JWT 없음)
  - frontend: 없음
- 근거: 보안점검서 I-3 · I-6 (`ports-prod-config.png`, `env-per-service.png`)

## 4. 환경 변수 · 비밀정보 관리

### 4.1 원칙
- `.env` 는 Git 에 올리지 않음 (`.gitignore`), 저장소에는 `.env.example`(값 없는 샘플)만
- 운영 `.env` 는 **EC2 의 Compose 파일과 같은 폴더에 하나**, 권한 `600` / 같은 값을 **GitHub Secrets 에도 등록**해 보관 (4.4)
- 운영 비밀값은 **로컬과 다른 새 값**으로 생성. 값에 `$` · 따옴표 금지 (Compose 가 `$` 를 변수로 해석)
- `.env.prod` 같은 운영 파일을 저장소에 두지 않음 → 로컬에서 만들 때도 **저장소 폴더 밖**에 보관
- 키 · 비밀번호를 코드 · 커밋 · 로그 · 캡처 · 발표 자료에 노출 금지 (CI 에서 gitleaks 로 전체 이력 검사)

### 4.2 로컬(개발) `.env`
- 저장소 최상위에서 `.env.example` 을 복사해 값 입력 (Backend · AI Module 이 **루트 `.env` 하나**를 함께 사용, `ai-module/.env` 별도 생성 안 함)
- `.env` 의 `DB_HOST=localhost` · `AI_SERVICE_URL=http://localhost:8000` 은 IDE 로 직접 실행할 때 값. Compose 로 실행하면 `docker-compose.yml` 이 컨테이너 주소(`database`, `http://ai-service:8000`)를 직접 지정
- LLM: `LLM_PROVIDER=groq`, `LLM_MODEL=openai/gpt-oss-20b` / 임베딩: `openai` · `text-embedding-3-small` (개발 · 배포 공통)
- 포트 충돌 시 `FRONTEND_LOCAL_PORT`(기본 80) · `DB_LOCAL_PORT`(기본 3306)만 변경

### 4.3 운영 `.env` 항목 (`docker-compose.prod.yml` 이 읽는 값)

| 변수 | 운영 값 | 비고 |
|------|---------|------|
| `DOCKERHUB_USERNAME` | Docker Hub 사용자명 | 이미지 경로 |
| `IMAGE_TAG` | `latest` (롤백 시 `sha-<커밋7자리>`) | 비우면 latest |
| `MARIADB_ROOT_PASSWORD` | **새로 생성** | |
| `MARIADB_DATABASE` | 로컬과 같은 DB 이름 가능 | |
| `MARIADB_USER` | 앱 전용 계정 (root 금지) | |
| `MARIADB_PASSWORD` | **새로 생성** | |
| `JWT_SECRET` | **새로 생성** (32바이트 이상) | 짧으면 backend 기동 실패 |
| `JWT_ACCESS_EXPIRATION` | `900000` (15분) | |
| `JWT_REFRESH_EXPIRATION` | `86400000` (1일) | |
| `CORS_ALLOWED_ORIGINS` | `http://<EC2 퍼블릭 IP 또는 주소>` | 로컬 값(`localhost:5173`) 쓰지 않음 |
| `ACTUATOR_EXPOSURE` | `health,info` | |
| `ADMIN_EMAIL` | 운영 관리자 이메일 | 기동 시 계정 생성 |
| `ADMIN_PASSWORD` | **새로 생성** | **8~20자 · 영문 · 숫자 · 특수문자** — 규칙에 안 맞으면 관리자 계정을 만들지 않음(`AdminInitializer`). 계정 생성 후에는 값을 바꿔도 기존 비밀번호는 그대로 |
| `AI_INTERNAL_TOKEN` | **새로 생성** | backend · ai-service 공통 |
| `LLM_PROVIDER` | 첫 배포 `groq` → 전환 후 `openai` | |
| `LLM_MODEL` | `openai/gpt-oss-20b` → 전환 후 `gpt-4o-mini` | |
| `GROQ_API_KEY` | Groq 키 | `openai` 전환 후 비워도 됨 |
| `EMBEDDING_PROVIDER` · `EMBEDDING_MODEL` | `openai` · `text-embedding-3-small` | 개발 · 배포 공통 |
| `OPENAI_API_KEY` | 강사 제공 키 | 임베딩은 첫 배포부터 필요 |
| `LOGIN_LOCK_MINUTES` | (선택) 기본 15 | 시연 때만 단축, 빈 값 금지 |

비밀값 생성 예 (Git Bash, **출력은 화면 · 캡처에 남기지 말고 바로 `.env` 에 입력**):
```bash
openssl rand -hex 32                     # JWT_SECRET, AI_INTERNAL_TOKEN
openssl rand -hex 24                     # MARIADB_ROOT_PASSWORD, MARIADB_PASSWORD
echo 'Adm!n1'"$(openssl rand -hex 6)"    # ADMIN_PASSWORD 18자 (영문 · 숫자 · 특수문자 포함, ! 는 작은따옴표 안에 — 큰따옴표면 bash 히스토리 확장 오류)
```

### 4.4 GitHub Secrets (값은 문서에 기재하지 않음)

운영 비밀값은 **GitHub Secrets(Repository secrets)에 등록해 보관**하고, EC2 `.env` 에는 **같은 값**을 입력합니다 (시스템 아키텍처 설계서 6.4 "GitHub Secrets → EC2 `.env`").

| 이름 | 용도 | 현재 사용처 |
|------|------|-------------|
| `DOCKERHUB_USERNAME` · `DOCKERHUB_TOKEN` | Docker Hub 로그인 · Push (Access Token, Read & Write) | `docker-build-push.yml` |
| `MARIADB_ROOT_PASSWORD` · `MARIADB_PASSWORD` | 운영 DB 비밀번호 | EC2 `.env` (수동 입력) |
| `JWT_SECRET` · `AI_INTERNAL_TOKEN` | 운영 JWT 서명 키 · Backend ↔ AI 내부 토큰 | EC2 `.env` |
| `ADMIN_EMAIL` · `ADMIN_PASSWORD` | 운영 관리자 계정 | EC2 `.env` |
| `OPENAI_API_KEY` · `GROQ_API_KEY` | LLM · 임베딩 API Key (강사 제공) | EC2 `.env` |
| (선택 · 가산 CD) `EC2_HOST` · `EC2_USER` · `EC2_SSH_KEY` | Actions 에서 EC2 자동 배포 | 현재 미사용 |

- 등록 순서: 4.3 의 명령으로 값 생성 → **EC2 `.env` 와 GitHub Secrets 에 같은 값 입력** → 화면 · 클립보드 · 임시 파일에서 지우기
- GitHub Secrets 는 저장 후 **값을 다시 볼 수 없음**(쓰기 전용) → EC2 `.env` 를 잃어버리면 값을 새로 만들어 Secrets 도 갱신 (DB 비밀번호는 기존 `db-data` 볼륨과 맞아야 하므로 바꿀 때 주의)
- 현재 CD 가 없어 Actions 가 앱 비밀값을 읽지 않음. EC2 자동 배포(가산)를 추가하면 이 Secrets 로 `.env` 를 만들도록 확장
- 등록 · 수정은 저장소 Admin 권한 필요, Actions 로그에 값이 출력되면 GitHub 가 `***` 로 가림

#### (4) 서버 준비 (SSH 접속 후)
```bash
# 로컬(Git Bash)에서 접속 — Windows 에서 .pem 권한 경고가 나면 icacls 로 본인만 읽기 허용
ssh -i <키페어>.pem ec2-user@<EC2 퍼블릭 IP>

# Docker 설치 · 자동 시작 · ec2-user 를 docker 그룹에 추가
sudo dnf install -y docker
sudo systemctl enable --now docker
sudo usermod -aG docker ec2-user
exit    # 그룹 반영을 위해 다시 접속

# Docker Compose v2 플러그인 설치 (버전은 github.com/docker/compose/releases 에서 확인 후 고정)
COMPOSE_VERSION=<버전 예: v2.x.y>
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -fsSL "https://github.com/docker/compose/releases/download/${COMPOSE_VERSION}/docker-compose-linux-x86_64" \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
docker compose version
```

#### (5) 파일 배치
```bash
# 로컬(저장소 최상위)에서 Compose 파일 복사 — 반드시 main 에 병합된 버전(git switch main && git pull)을 복사
ssh -i <키페어>.pem ec2-user@<EC2 퍼블릭 IP> "mkdir -p ~/asknote"
scp -i <키페어>.pem docker-compose.prod.yml ec2-user@<EC2 퍼블릭 IP>:~/asknote/
# 운영 .env (저장소 밖에서 작성한 파일) 복사 후 권한 600
scp -i <키페어>.pem <저장소 밖 경로>/asknote.env ec2-user@<EC2 퍼블릭 IP>:~/asknote/.env
# Windows 에서 만든 파일은 줄바꿈이 CRLF 일 수 있음 → 값 끝에 \r 이 붙어 비밀번호 · 토큰이 달라짐 → LF 로 변환 후 권한 600
ssh -i <키페어>.pem ec2-user@<EC2 퍼블릭 IP> "sed -i 's/\r\$//' ~/asknote/.env && chmod 600 ~/asknote/.env && ls -l ~/asknote"
```

#### (6) 배포
```bash
cd ~/asknote
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps        # 4개 모두 (healthy) 확인
```

#### (9) 갱신 · 롤백
```bash
# 새 버전 (main 병합 → Actions Push 후)
docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d
# 롤백: .env 의 IMAGE_TAG 를 이전 sha 태그(예: sha-1a2b3c4)로 바꾼 뒤
docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d
```
- 주의: 새 버전에서 Flyway 마이그레이션(V2 등)이 이미 적용됐다면, 이전 backend 이미지는 `ddl-auto: validate` 에서 스키마 불일치로 기동 실패할 수 있음 → 마이그레이션이 포함된 배포는 롤백 전에 DB 백업 · 스키마 호환 여부 확인

#### (10) 문제 해결
| 증상 | 원인 · 조치 |
|------|-------------|
| `permission denied ... docker.sock` | `usermod` 후 재접속 안 함 → `exit` 후 다시 SSH |
| `.env 에 XXX 를 설정하세요` | 운영 `.env` 누락 · 오타 → 4.3 표와 비교 |
| backend `unhealthy` | `docker compose -f docker-compose.prod.yml logs --tail=100 backend` — JWT_SECRET 32바이트 미만, DB 비밀번호 불일치(기존 `db-data` 볼륨) 확인 |
| 브라우저 접속 안 됨 | 보안그룹 80 허용 · frontend `healthy` 확인 |
| 컨테이너가 반복 재시작 | `docker stats` 로 메모리 확인 → `mem_limit` 조정 |
| 관리자 계정으로 로그인 안 됨 | `logs backend` 에 "비밀번호 규칙에 맞지 않아" → `ADMIN_PASSWORD` 를 8~20자 · 영문 · 숫자 · 특수문자로 바꾸고 backend 재생성 (이미 계정이 있으면 값 변경이 반영되지 않음) |
| 화면에 "요청이 너무 많습니다" (429) | IP 별 요청 제한 초과 → 1분 정도 후 재시도. 시연 때 같은 Wi-Fi 에서 여러 명이 동시에 로그인 · 질문하면 한도를 나눠 씀 |

## 6. CI/CD

| 워크플로 | 트리거 | 내용 |
|----------|--------|------|
| `docker-build-push.yml` | PR(develop · main): 빌드만 / **main push: 빌드 + Push** / 수동 실행 | 이미지 3종 matrix 빌드, 태그 `latest` + `sha-<7자리>`, GHA 캐시, `permissions: contents: read` |
| `secret-scan.yml` | main · develop push, 모든 PR, 수동 실행 | gitleaks 8.21.2 전체 Git 이력 검사(체크섬 검증), 다운로드 장애 시 재시도 · 같은 버전 공식 이미지(digest 고정)로 대체, Ruleset 필수 check |

- 흐름: 작업 브랜치 → PR(리뷰 1명) → `develop` → 배포 직전 PR → `main` → Actions 가 이미지 3종 Push → EC2 에서 `pull && up -d`
- 3종을 항상 같은 커밋 태그로 함께 빌드 → `IMAGE_TAG=sha-…` 하나로 같은 시점 롤백
- EC2 자동 배포(CD)는 미적용 (수동 `pull && up -d`)
