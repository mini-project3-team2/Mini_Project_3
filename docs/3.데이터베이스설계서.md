# 데이터베이스 설계서

> 버전 v0.2 (초안) · 작성 윤수연 · 2026-11-06 팀 검토 후 확정
> 서비스: AskNote (수업 자료 기반 AI 학습 도우미)
> 스키마는 Flyway(`V1__init.sql`)로 생성하고 JPA는 `ddl-auto=validate`로 검증만 한다

## 1. 데이터베이스 구성

- **RDBMS**: MariaDB (회원, 리프레시 토큰, 내 자료 정보, 질문 기록)
- **Vector DB**: Chroma (자료 청크 · 임베딩, AI Module 컨테이너 볼륨에 영속화)

| 구분 | 저장 위치 | 외부 공개 |
|------|-----------|-----------|
| MariaDB | `database` 컨테이너, 볼륨 `db-data` | 비공개 (Compose `ports` 미게시) |
| Chroma | `ai-service` 컨테이너, 볼륨 `chroma-data` | 비공개 |

> 업로드한 원본 PDF는 저장하지 않는다 (청크 · 임베딩만 Chroma에 저장). 분할 설정을 바꿀 때는 자료를 다시 업로드해 재적재한다

## 2. 주요 테이블

> 공통: 테이블 · 컬럼명은 snake_case, 문자셋 `utf8mb4`, 시각은 `DATETIME`(서버 시간대 Asia/Seoul)

### 2.1 members (회원)

| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|----------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 내부 식별자 (외부 노출 안 함) |
| uuid | CHAR(36) | UNIQUE, NOT NULL | 외부 식별자, JWT subject, Chroma 소유자 필터 값 |
| email | VARCHAR(100) | UNIQUE, NOT NULL | 로그인 ID |
| password | VARCHAR(255) | NOT NULL | BCrypt 해시 |
| role | VARCHAR(20) | NOT NULL, DEFAULT 'MEMBER' | MEMBER / ADMIN (ADMIN은 Actuator 접근용, 화면 없음) |
| failed_login_count | INT | NOT NULL, DEFAULT 0 | 연속 로그인 실패 횟수 (성공 시 0) |
| locked_until | DATETIME | NULL | 잠금 해제 시각 (5회 실패 시 15분 잠금, 팀 검토 후 확정) |
| created_at | DATETIME | NOT NULL | 가입 시각 |

### 2.2 refresh_tokens (리프레시 토큰)

| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|----------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 토큰 ID |
| member_id | BIGINT | FK → members.id, NOT NULL | 소유 회원 (기기별 여러 개 허용) |
| token_hash | CHAR(64) | UNIQUE, NOT NULL | 토큰 원문의 SHA-256 해시 (원문 저장 안 함) |
| expires_at | DATETIME | NOT NULL | 만료 시각 (발급 후 1일) |
| created_at | DATETIME | NOT NULL | 발급 시각 |

- 재발급(회전): 기존 행 삭제 → 새 행 저장 / 로그아웃: 해당 행 삭제

### 2.3 documents (내 자료)

| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|----------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 문서 ID (Chroma 메타데이터 `document_id`와 연결) |
| member_id | BIGINT | FK → members.id, NOT NULL | 소유 회원 (소유자 검증 기준) |
| original_filename | VARCHAR(255) | NOT NULL | 업로드한 원래 파일명 (화면 · 출처 표시용) |
| file_size | BIGINT | NOT NULL | 바이트 (최대 10MB) |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'INDEXING' | INDEXING(적재 중) / READY(적재 완료) — **READY인 문서만 답변에 사용** |
| created_at | DATETIME | NOT NULL | 업로드 시각 (목록 정렬 기준) |

- 업로드는 **동기 적재**: 행 저장(INDEXING) → AI 적재 요청 → 성공하면 READY로 변경 후 응답 / 실패 · 타임아웃이면 AI 청크 삭제 요청 → 행 삭제 → 오류 응답
- **원본 PDF는 서버에 저장하지 않는다**: 적재에만 쓰고, 요청이 끝나면 Spring 임시 파일과 함께 삭제됨 (다운로드 기능 없음, 서버에 사용자 파일을 남기지 않음)

### 2.4 chat_histories (질문 기록)

| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|----------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 기록 ID |
| member_id | BIGINT | FK → members.id, NOT NULL | 질문한 회원 (소유자 검증 기준) |
| question | VARCHAR(1000) | NOT NULL | 질문 (최대 1000자) |
| answer | TEXT | NOT NULL | 스트리밍으로 전달한 답변 전체 |
| sources | JSON | NULL | 근거 출처 `[{documentId, documentName, page}]` — 문서를 삭제해도 기록에는 당시 이름이 남음 |
| feedback | VARCHAR(20) | NULL | 답변 피드백: HELPFUL(도움됨) / NOT_HELPFUL(도움 안 됨), 미선택은 NULL |
| created_at | DATETIME | NOT NULL | 질문 시각 (목록 정렬 기준) |

- 답변 스트리밍이 **정상 완료됐을 때만 저장** (오류 · 중단 시 저장하지 않음 → 상태 컬럼 없음)
- 피드백은 사용자가 버튼을 누를 때 수정 (다시 누르면 값 변경)

**인덱스**

| 테이블 | 인덱스 | 용도 |
|--------|--------|------|
| refresh_tokens | `idx_refresh_member (member_id)` | 회원별 토큰 조회 |
| documents | `idx_documents_member_created (member_id, created_at)` | 내 자료 목록 |
| documents | `idx_documents_member_status (member_id, status)` | 질문 시 READY 문서 id 조회 |
| chat_histories | `idx_chat_member_created (member_id, created_at)` | 내 질문 기록 페이징 |

## 3. 관계

```
members 1 ──── N refresh_tokens
members 1 ──── N documents ┄┄┄ (document_id · owner_uuid 메타데이터) ┄┄┄ N Chroma 청크
members 1 ──── N chat_histories
```

- Member (1:N) RefreshToken, Member (1:N) Document, Member (1:N) ChatHistory — 모두 `@ManyToOne(fetch = LAZY)` 단방향 (Member 쪽 컬렉션 없음)
- chat_histories와 documents는 FK로 묶지 않는다 (출처는 JSON 스냅샷) → 문서를 삭제해도 질문 기록은 유지

**주요 규칙**
- 목록은 항상 로그인 회원 조건으로만 조회하고, 삭제 · 피드백 수정은 `id + member_id` 조건으로 한다 → 남의 데이터는 403
- 문서 삭제 순서: **Chroma 청크 삭제 → DB 행 삭제**
- **DB가 기준**: 질문할 때 Backend가 해당 회원의 READY 문서 id 목록을 AI에 넘기고, AI는 그 목록 안에서만 검색한다 → 적재 실패 · 타임아웃 · 삭제 실패로 Chroma에 청크가 남아도 답변에 쓰이지 않음
- 적재 중 서버가 멈춰 INDEXING으로 남은 문서는 목록에 "적재 중"으로 보이며, 사용자가 삭제할 수 있다
- 관리자 계정은 Flyway에 비밀번호를 넣지 않고, 기동 시 환경 변수(`ADMIN_EMAIL`, `ADMIN_PASSWORD`)로 생성

## 4. 벡터 DB 설정

| 항목 | 값 | 비고 |
|------|----|------|
| 저장소 | Chroma (PersistentClient, 볼륨 `chroma-data`) | AI Module 내부 |
| 컬렉션 | `study_materials_{임베딩 모델명}` → `study_materials_text-embedding-3-small` | 전 사용자 공용 컬렉션 + **`owner_uuid` 메타데이터 필터로 사용자 격리**. 모델을 바꾸면 벡터가 호환되지 않아 이름에 모델명을 넣음 |
| 임베딩 모델 | OpenAI `text-embedding-3-small`(1536차원), 개발 · 테스트 · 배포 공통 | `EMBEDDING_PROVIDER=openai` · `EMBEDDING_MODEL=text-embedding-3-small`. 개발 데이터는 배포로 복사하지 않음 (회원 · 문서 id가 환경마다 다름) |
| 로더 · 분할 | `PyPDFLoader`로 페이지별 로드 → `RecursiveCharacterTextSplitter` | PDF만 지원 |
| 청크 크기 · 오버랩 | 800자 · 100자 | 통합(11/9) 때 답변 품질 보고 조정 |
| 검색 | similarity, k = 4, `where = {"$and": [{"owner_uuid": 토큰의 uuid}, {"document_id": {"$in": READY 문서 id 목록}}]}` | 필요 시 mmr 비교 |
| 적재 실패 처리 | 적재 중 예외가 나면 해당 `document_id`의 청크를 지우고 오류 응답 | 잔재 최소화 (답변 차단은 위 `$in` 조건이 담당) |
| 자료에 없는 질문 | 프롬프트에 "자료에 없으면 모른다고 답할 것" 지시 | 별도 점수 기준 없음 |
| 메타데이터 | `owner_uuid`, `document_id`, `document_name`, `page`(PDF 페이지 번호, 1부터) | 출처 표시 · 소유자 필터 · 문서 삭제 시 청크 삭제 |

> `owner_uuid`는 Backend가 **JWT에서 꺼낸 값**으로만 채운다. 요청 body로 받은 값은 쓰지 않는다 (RAG 소유자 우회 방지)
