# Backend 개발 명세서

> AskNote (수업 자료 기반 AI 학습 도우미) · 작성 윤수연 (Backend 1)
> 기준 문서: `3.데이터베이스설계서.md`, `4.API설계서.md`, `2.시스템아키텍처설계서.md`
> 점검 · 조치 결과는 `9.보안점검서.md`에 기록하고, 이 문서는 **구현 방식**을 기술한다

## 1. 기술 스택

| 구분 | 기술 |
|------|------|
| Framework | Spring Boot 4.0.9 (Spring Security 7, Spring Web MVC) |
| 언어 | Java 17 |
| 데이터베이스 | MariaDB 10.11 (`mariadb-java-client`) |
| 데이터 접근 | Spring Data JPA (Hibernate), `ddl-auto: validate` |
| 스키마 관리 | Flyway (`spring-boot-starter-flyway` + `flyway-mysql`) |
| 인증 | JWT (jjwt 0.12.6, HS256), BCrypt |
| AI 연동 | WebClient (`spring-boot-starter-webflux`) — 적재 호출 · SSE 스트림 수신 |
| 화면 스트리밍 | `SseEmitter` (Server-Sent Events) |
| 기타 | Bean Validation, Actuator, Lombok |
| 빌드 | Maven (Maven Wrapper) |

## 2. 프로젝트 구조

계층별 패키지 구조 (`controller → service → repository → entity`)를 사용한다.

```
backend/
├── src/main/java/com/asknote/
│   ├── BackendApplication.java
│   ├── config/       # SecurityConfig(인가 · CORS), PasswordConfig, AiClientConfig(WebClient),
│   │                 # AdminInitializer, LocalDataInitializer(local 프로필 전용)
│   ├── security/     # JwtTokenProvider, JwtAuthenticationFilter, JwtCurrentMemberProvider,
│   │                 # RefreshTokenUtil, JsonAuthenticationEntryPoint(401), JsonAccessDeniedHandler(403)
│   ├── controller/   # AuthController, DocumentController, ChatController
│   ├── service/      # AuthService, DocumentService, PdfValidator, ChatStreamService, ChatHistoryService
│   ├── client/       # AiDocumentClient(적재 · 청크 삭제), AiQueryClient(질의 스트리밍)
│   ├── repository/   # MemberRepository, RefreshTokenRepository, DocumentRepository, ChatHistoryRepository
│   ├── entity/       # Member, RefreshToken, Document, ChatHistory + Role, DocumentStatus, Feedback
│   ├── dto/          # auth/ · document/ · chat/ · ai/ 요청 · 응답 DTO (엔티티를 응답에 직접 쓰지 않음)
│   └── common/       # ApiResponse · PageResponse, exception/(ErrorCode · BusinessException ·
│                     # GlobalExceptionHandler), auth/CurrentMemberProvider, audit/AuditLogger
├── src/main/resources/
│   ├── application.yaml       # 비밀정보는 ${ENV} 참조만
│   └── db/migration/V1__init.sql
├── scripts/                   # 점검 스크립트, 로컬 확인용 가짜 AI 서버
└── pom.xml
```

## 3. 주요 설정

### 3.1 `application.yaml`

```yaml
spring:
  config:
    # 루트 .env 를 읽는다 (파일이 없으면 무시 → 컨테이너에서는 환경 변수 사용)
    import: "optional:file:.env[.properties],optional:file:../.env[.properties]"
  datasource:
    url: jdbc:mariadb://${DB_HOST}:${DB_PORT}/${MARIADB_DATABASE}
    username: ${MARIADB_USER}        # root 가 아닌 앱 전용 계정
    password: ${MARIADB_PASSWORD}
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 11MB
  jpa:
    hibernate:
      ddl-auto: validate             # 스키마는 Flyway 로만 변경
    open-in-view: false              # 응답(특히 SSE) 중에 DB 연결을 붙잡지 않음

server:
  forward-headers-strategy: native   # Nginx 뒤에서 실제 접속 IP (감사 로그)
  tomcat:
    max-swallow-size: 12MB

jwt:
  secret: ${JWT_SECRET}
  access-expiration: ${JWT_ACCESS_EXPIRATION}     # 900000 (15분)
  refresh-expiration: ${JWT_REFRESH_EXPIRATION}   # 86400000 (1일)

auth:
  login:
    max-attempts: ${LOGIN_MAX_ATTEMPTS:5}
    lock-minutes: ${LOGIN_LOCK_MINUTES:15}

ai:
  service-url: ${AI_SERVICE_URL:http://localhost:8000}
  internal-token: ${AI_INTERNAL_TOKEN:}
  timeout:
    ingest-seconds: 120
    delete-seconds: 10
    stream-seconds: 60

cors:
  allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:5173}

management:
  endpoints:
    web:
      exposure:
        include: ${ACTUATOR_EXPOSURE:health,info}
  endpoint:
    health:
      show-details: never
```

### 3.2 환경 변수

| 변수 | 용도 | 비고 |
|------|------|------|
| `DB_HOST` · `DB_PORT` · `MARIADB_DATABASE` · `MARIADB_USER` · `MARIADB_PASSWORD` | DB 연결 | Compose 에서는 `DB_HOST=database` |
| `JWT_SECRET` | JWT 서명 키 | 32바이트 이상, 미만이면 기동 실패 |
| `JWT_ACCESS_EXPIRATION` · `JWT_REFRESH_EXPIRATION` | 토큰 만료(ms) | 15분 · 1일 |
| `CORS_ALLOWED_ORIGINS` | 허용 출처 (쉼표 구분) | 와일드카드 사용 안 함 |
| `ACTUATOR_EXPOSURE` | Actuator 노출 항목 | `health,info` |
| `ADMIN_EMAIL` · `ADMIN_PASSWORD` | 관리자 계정 생성 | 비어 있으면 생성 안 함 |
| `AI_SERVICE_URL` · `AI_INTERNAL_TOKEN` | AI Module 주소 · 내부 인증 토큰 | Compose 에서는 `http://ai-service:8000` |
| `LOGIN_MAX_ATTEMPTS` · `LOGIN_LOCK_MINUTES` | 로그인 잠금 기준 | 선택, 기본 5회 · 15분 |

### 3.3 프로필

| 프로필 | 용도 |
|------|------|
| (기본) | 운영 · 통합. 실제 보안 설정만 동작 |
| `local` | 로컬 개발 전용. `LocalDataInitializer`가 테스트 계정(student · other) · 자료 · 기록을 생성. **배포에서는 켜지 않는다** |

## 4. 주요 클래스

### 4.1 Entity

| 클래스 | 테이블 | 설명 |
|--------|------|------|
| Member | `members` | 회원. 내부 id + 외부 식별자 uuid(JWT subject), role(MEMBER · ADMIN), 로그인 실패 횟수 · 잠금 시각 |
| RefreshToken | `refresh_tokens` | Refresh Token의 SHA-256 해시 · 만료 시각 (원문 저장 안 함) |
| Document | `documents` | 내 자료 메타데이터 (파일명 · 크기 · status INDEXING/READY). 원본 PDF는 저장하지 않음 |
| ChatHistory | `chat_histories` | 질문 · 답변 · 출처(JSON 스냅샷) · 피드백 |

- 모든 연관은 `@ManyToOne(fetch = LAZY)` 단방향 (Member 쪽 컬렉션 없음)
- enum 컬럼은 `@Enumerated(STRING)` + `@JdbcTypeCode(SqlTypes.VARCHAR)` → DB `VARCHAR(20)`과 `validate` 일치

### 4.2 Controller

| 클래스 | 엔드포인트 | 설명 |
|--------|------|------|
| AuthController | `POST /api/auth/signup` · `login` · `refresh` · `logout` | 회원가입 201, 로그인 · 재발급 200, 로그아웃 204 |
| DocumentController | `POST /api/documents` · `DELETE /api/documents/{id}` · `GET /api/documents` | 목록(최신순) 200, 업로드(적재 완료 후 201), 삭제 204 |
| ChatController | `POST /api/chats/stream` · `GET /api/chats` · `PATCH /api/chats/{id}/feedback` | 답변 SSE 스트리밍, 기록 목록(최신순 · 페이징) 200, 피드백 200 |

### 4.3 Service

| 클래스 | 설명 |
|--------|------|
| AuthService | 회원가입(이메일 중복 409), 로그인(실패 횟수 · 계정 잠금), 토큰 발급 · 회전 · 폐기 |
| DocumentService | 업로드 동기 적재(INDEXING → AI 적재 → READY / 실패 시 정리), 삭제(소유자 확인 → 청크 삭제 → 204면 행 삭제, 실패하면 503 `AI_UNAVAILABLE`로 행 유지) |
| PdfValidator | 업로드 파일 검증 (빈 파일 · 10MB · 확장자 `.pdf` · `%PDF-` 시그니처) |
| ChatStreamService | READY 문서 id 조회 → AI 질의 스트림 → 화면 SSE 중계, `done` 때 기록 저장 |
| ChatHistoryService | 기록 목록(최신순 · page ≥ 0 · size 1~50, 출처 JSON → 배열), 피드백 등록 · 변경(소유자 확인, 없으면 404 · 남의 기록 403) |

### 4.4 Repository

| 클래스 | 주요 메서드 |
|--------|------|
| MemberRepository | `findByEmail`, `findByUuid`, `existsByEmail`, `findByEmailForUpdate`(로그인 시 행 잠금) |
| RefreshTokenRepository | `findByTokenHash` |
| DocumentRepository | `findByMemberIdOrderByCreatedAtDescIdDesc`(내 자료 목록, 같은 시각이면 id 큰 순), `findIdsByMemberIdAndStatus`(READY 문서 id), `findWithMemberById`(삭제 시 소유자 함께 조회) |
| ChatHistoryRepository | `findByMemberId(memberId, Pageable)`(기록 목록, createdAt desc → id desc), `findWithMemberById`(피드백 시 소유자 함께 조회) |

### 4.5 공통

| 클래스 | 설명 |
|--------|------|
| `ApiResponse<T>` | 공통 응답 `{success, data, message, code}` (성공 시 `code` 생략) |
| `PageResponse<T>` | 페이지 응답 `{content, page, size, totalElements, totalPages}` |
| `ErrorCode` | 오류 코드 · HTTP 상태 · 사용자 문구 (API 설계서 · mock-data와 동일) |
| `BusinessException` | 업무 예외 (`ErrorCode` + 선택 data, 예: 잠금 해제 시각) |
| `CurrentMemberProvider` | 로그인 회원 조회 인터페이스 — 서비스는 이것으로만 회원을 얻고 요청 값의 회원 id · uuid를 쓰지 않음 |
| `AuditLogger` | 감사 로그 (로거 `AUDIT`) |

## 5. 보안 구현

### 5.1 인증 · 인가

**Security FilterChain (`SecurityConfig`)**

| 경로 | 접근 |
|------|------|
| `POST /api/auth/signup` · `login` · `refresh` | 공개 |
| `GET /actuator/health` | 공개 (UP/DOWN만) |
| 그 밖의 `/actuator/**` | ADMIN |
| 그 외 전부 | 로그인 필요 (`anyRequest().authenticated()`) |
| ASYNC · ERROR 디스패치 | 허용 (SSE 응답 중 내부 재디스패치, 최초 요청에서 이미 인증 · 인가됨) |

- 세션 미사용(`STATELESS`), `formLogin` · `httpBasic` 비활성
- `JwtAuthenticationFilter`: `Authorization: Bearer` 토큰 검증 → SecurityContext에 uuid · `ROLE_x` 저장. 토큰이 없거나 유효하지 않으면 인증 없이 통과 → 보호 경로면 EntryPoint가 401
- 401 · 403은 `JsonAuthenticationEntryPoint` · `JsonAccessDeniedHandler`가 공통 오류 형식으로 응답

**JWT · Refresh Token**

| 항목 | 구현 |
|------|------|
| Access Token | HS256, subject = 회원 uuid(내부 id 미노출), `role` 클레임, 15분 |
| Refresh Token | JWT가 아닌 32바이트 무작위 값(Base64 URL), DB에는 **SHA-256 해시만** 저장, 1일 |
| 재발급 (회전) | 해시로 조회 → 기존 행 삭제 → 새 Access · Refresh 발급. 한 번 쓴 Refresh는 401 |
| 로그아웃 | 로그인 회원 본인의 Refresh 행만 삭제 → 204 |
| 키 관리 | `JWT_SECRET` 환경 변수, 32바이트 미만이면 기동 실패 |

**소유자 검증 (IDOR 방지)**

- 로그인 회원은 `CurrentMemberProvider`(JWT의 uuid → DB 조회)로만 얻는다
- 자료 삭제: 문서를 소유자와 함께 조회 → `document.isOwnedBy(member.getId())`가 아니면 403 + 감사 로그 `OWNERSHIP_DENIED`
- 답변 피드백: 기록을 소유자와 함께 조회 → `chat.isOwnedBy(member.getId())`가 아니면 403 + 감사 로그 `OWNERSHIP_DENIED`
- 자료 목록 · 기록 목록: JWT 회원 id로만 조회 (요청 값으로 회원을 받지 않음)
- 질문: 검색 소유자(`ownerUuid`) · 문서 id 목록은 JWT 회원과 DB에서만 만든다 (요청 body 값 사용 안 함)

### 5.2 공격 방어

| 위협 | 방어 방식 | 구현 위치 |
|------|-----------|-----------|
| SQL Injection | JPA 메서드 쿼리 · `@Query`의 `:param` 바인딩 (문자열 연결 쿼리 없음) | `repository/` |
| Brute Force | 연속 5회 실패 → 15분 잠금(423), 잠금 중엔 올바른 비밀번호도 거부. 실패 횟수가 롤백되지 않도록 `noRollbackFor`, 동시 시도 대비 회원 행 잠금(`PESSIMISTIC_WRITE`) | `AuthService.login`, `MemberRepository.findByEmailForUpdate` |
| 계정 존재 확인 | 이메일이 없든 비밀번호가 틀리든 같은 401 `INVALID_CREDENTIALS` | `AuthService.login` |
| CSRF | **비활성** — 쿠키로 인증하지 않고 `Authorization` 헤더 · body로 토큰을 주고받으므로 브라우저가 자동으로 인증 정보를 붙이지 않음. 변경 · 삭제에 GET을 쓰지 않음 | `SecurityConfig` |
| XSS | API는 JSON만 응답. 보안 헤더(CSP · nosniff · X-Frame-Options)는 Nginx에서 적용, 화면은 텍스트 렌더링 | Nginx `nginx.conf`, Frontend |
| IDOR | 소유자 검증 (5.1) | `DocumentService`, `ChatStreamService`, `ChatHistoryService` |
| 입력값 검증 | DTO `@Valid` — 이메일 형식 · 100자, 비밀번호 8~20자 영문 · 숫자 · 특수문자, 질문 1~1000자, 피드백 `HELPFUL` · `NOT_HELPFUL`만(숫자 순번 불가), 기록 목록 page ≥ 0 · size 1~50 | `dto/` |
| 비밀번호 저장 | BCrypt | `PasswordConfig` |
| 파일 업로드 | PDF만(확장자 + `%PDF-`), 10MB 제한, 파일명에서 경로 · 제어 문자 제거 · 255자, 원본 미저장 | `PdfValidator`, `DocumentService`, `application.yaml` |

### 5.3 설정 · 로그

- **CORS**: `CORS_ALLOWED_ORIGINS`만 허용, 메서드 `GET · POST · PATCH · DELETE · OPTIONS`, 헤더 `Authorization · Content-Type`, `/api/**`에만 적용
- **Actuator**: `health,info`만 노출, `health`만 공개 · 상세 미노출, 나머지 ADMIN. 운영에서는 Nginx가 `/actuator`를 404로 막음
- **관리자 계정**: Flyway에 비밀번호를 넣지 않고 기동 시 `ADMIN_EMAIL` · `ADMIN_PASSWORD`로 생성 (`AdminInitializer`)
- **감사 로그** (`AuditLogger`, 로거 `AUDIT`)

| 이벤트 | 기록 내용 |
|------|------|
| `SIGNUP` · `LOGIN_SUCCESS` · `LOGOUT` | 이메일(마스킹) · IP |
| `LOGIN_FAILURE` · `ACCOUNT_LOCKED` | 이메일(마스킹) · IP |
| `REFRESH_FAILURE` | IP |
| `ACCESS_DENIED` (403) | 대상(메서드 · URI) · IP |
| `OWNERSHIP_DENIED` (남의 자료 접근) | 이메일(마스킹) · 대상 |

- 이메일 마스킹 예: `student@test.com` → `st***@test.com`, 줄바꿈 제거(로그 위조 방지). 비밀번호 · 토큰 · API Key는 기록하지 않음
- **예외 처리**: 500은 서버 로그에만 스택 트레이스, 응답은 `INTERNAL_SERVER_ERROR` 고정 문구

## 6. AI 모듈 연동

| 항목 | 구현 |
|------|------|
| 클라이언트 | `AiClientConfig`에서 `WebClient` 생성 (`AI_SERVICE_URL`, 모든 요청에 `X-Internal-Token`) |
| 적재 | `AiDocumentClient.ingest` — multipart(`file` · `documentId` · `ownerUuid` · `documentName`), 120초 |
| 청크 삭제 | `AiDocumentClient.deleteChunks` — `DELETE /internal/documents/{id}?ownerUuid=`, 10초, 성공 여부를 `true` · `false`로 반환 (예외를 던지지 않음) → 실패하면 `DocumentService`가 행을 남김 |
| 질의 스트리밍 | `AiQueryClient.stream` — `POST /internal/query/stream` SSE 수신, 이벤트 간격 60초 초과 시 타임아웃 |
| 오류 변환 | 적재: AI 422 → `TEXT_EXTRACTION_FAILED`(422), 그 밖의 오류 · 연결 실패 · 타임아웃 → `AI_UNAVAILABLE`(503) / 스트리밍: AI `error` · 타임아웃 · 연결 오류 → 고정 문구 `error` 이벤트, 원인 코드는 서버 로그에만 |
| 재시도 · Fallback | 자동 재시도 · 대체 모델 없음 (적재 중복 · 비용 방지). 사용자에게 재시도 안내 문구 |

**업로드 흐름 (`DocumentService.upload`)**

1. 로그인 회원 조회 → `PdfValidator` 검증
2. `documents` 행 저장 (`INDEXING`)
3. AI 적재 요청 (120초 대기)
4. 성공 → `READY`로 변경 후 201 / 실패 → AI 청크 삭제 요청 → 204면 행 삭제 → 오류 응답
   - 청크 삭제도 실패하면 행을 `INDEXING`으로 남김 (타임아웃 뒤 AI 적재가 계속되는 경우 대비) → 화면에서 삭제하면 다시 정리

- 메서드에 트랜잭션을 걸지 않음 → 적재 대기 동안 DB 연결 · 트랜잭션을 붙잡지 않음 (각 저장은 즉시 커밋)

**질문 흐름 (`ChatStreamService`)**

1. 스트림 시작 전: 질문 검증, 로그인 회원의 READY 문서 id 조회 (없으면 400 `NO_DOCUMENT`) → 일반 JSON 오류
2. AI 질의 요청 `{question, ownerUuid(JWT 회원), documentIds}`
3. `sources` · `token`은 화면으로 그대로 중계, `token`의 `text`는 모아 둠
4. `done` → 질문 · 답변 · 출처를 `chat_histories`에 저장 → `{"chatId": n}` 전송
   - 거절 답변(공백 제거 후 80자 이하 + "올린자료에서관련내용을찾지못했어요" 포함)은 출처를 `[]`로 저장 (관련 없는 출처가 기록에 남지 않게)
5. 화면 연결이 끊기면 AI 구독 해제 (기록 저장 안 함)

- 응답 헤더: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`

## 7. 파일 처리

| 항목 | 내용 |
|------|------|
| 업로드 | `MultipartFile` (`multipart/form-data`, 필드 `file`) |
| 지원 형식 | **PDF만** (확장자 `.pdf` + 파일 앞 `%PDF-` 시그니처) |
| 크기 | 파일 10MB · 요청 11MB · Tomcat 12MB (Nginx 12MB), 초과 시 413 `FILE_TOO_LARGE` |
| 저장 | **원본을 저장하지 않음** — 적재에만 쓰고 요청이 끝나면 임시 파일 삭제. DB에는 표시용 파일명 · 크기만 |
| 파일명 | 경로 문자(`/` · `\`) · 제어 문자 제거, 255자 제한, 비어 있으면 `document.pdf` |

## 8. 예외 처리

- **`GlobalExceptionHandler`** (`@RestControllerAdvice`): 모든 오류를 공통 형식으로 변환

| 예외 | 응답 |
|------|------|
| `BusinessException` | `ErrorCode`의 상태 · 문구 (+ data) |
| `MethodArgumentNotValidException` | 400 `INVALID_INPUT`, 첫 번째 필드의 검증 문구 |
| JSON 파싱 · 타입 불일치 · 필수 파라미터 누락 | 400 `INVALID_INPUT` |
| `MaxUploadSizeExceededException` | 413 `FILE_TOO_LARGE` |
| `AccessDeniedException` | 403 `FORBIDDEN` |
| `NoResourceFoundException` · 지원하지 않는 메서드 | 404 `NOT_FOUND` · 405 `METHOD_NOT_ALLOWED` |
| 그 외 `Exception` | 500 `INTERNAL_SERVER_ERROR` (상세는 서버 로그에만) |

- **Custom Exception**: `BusinessException` + `ErrorCode` enum (19개 코드)
- 필터 단계(컨트롤러 밖)의 401 · 403은 `SecurityErrorWriter`가 같은 형식으로 작성
