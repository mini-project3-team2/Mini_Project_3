## 배포 전 판단할 문제

| 항목 | 재현 및 영향 | 조치와 재확인 방법 |
|---|---|---|
| 감사 로그 IP 위조 | Nginx 경유로 존재하지 않는 동일 테스트 계정에 로그인했다. 헤더 없이 401, 감사 IP는 Docker 게이트웨이였다. `X-Forwarded-For: 198.51.100.77`을 추가해도 401이었지만 감사 IP가 그 값으로 바뀌었다. 장애·사고 추적 시 출발지를 잘못 식별할 수 있다. 사설 프록시 홉이 있는 로컬 경로에서 재현했다. Nginx 요청 제한 키는 연결 주소를 사용한다. | 외부 요청을 직접 받는 Nginx에서 공통 프록시 설정과 스트리밍 location 모두 XFF를 `$remote_addr`로 덮어쓴다. 신뢰할 로드밸런서가 있다면 해당 홉만 명시한다. 위조 헤더 유무에 따른 감사 IP가 같은지 확인한다. |

## 직접 실행한 회귀 점검

[스크립트별 기대값과 실제 응답, RAG 출처](regression-2026-11-10.txt)

- 기존 로컬 DB와 다른 Compose 프로젝트, 루프백 포트, 임시 자격증명을 사용했다. 인증·자료·피드백·SQLi·업로드·채팅·무차별 대입 7종을 실행했다. 가짜 AI와 local 프로필 시드 계정이 필요한 스크립트는 해당 환경에서 실행했다. 관리자 자격증명 동기화 후 인증 스크립트를 다시 실행하여 MEMBER 403, ADMIN 200을 확인했다.
- 자료 삭제와 피드백 수정 IDOR는 403이었다. 다른 계정의 피드백 값이 유지됐다. 5번째 로그인 실패부터 423이었고 올바른 비밀번호도 잠금 중 423이었다. Nginx 연속 인증 요청에는 429가 반환됐다. `/.env`와 `/actuator/health`의 외부 경로는 CSP 헤더와 함께 404였다.
- 실제 발급 토큰은 보호 경로에서 200이었다. 무서명, 정상 키로 서명한 만료 토큰, 서명 유지·role 변경, 다른 키 서명은 모두 401이었다. 로그아웃 직후 같은 Access는 200, 폐기한 Refresh는 401, 다른 세션의 Refresh는 200이었다. 중복 이메일 가입은 409 `DUPLICATE_EMAIL`로 가입 여부를 구별할 수 있었다.
- 실제 RAG 스크립트까지 총 8종을 실행했다. 승인된 두 샘플 PDF를 별도 계정에서 업로드하여 각각 READY를 확인했다. A의 카이사르 암호 질문에는 A의 PDF가 출처로 등장했다. B 토큰으로 같은 질문에 A의 ownerUuid와 documentIds를 추가하자 답변은 관련 자료가 없다고 안내했고, 응답 출처와 DB를 통해 조회한 B의 최신 기록 출처가 모두 비었다.
- Backend Maven 테스트 33개가 모두 통과했다. 첫 시도에서 컨텍스트 테스트의 DB 연결이 실패해 격리 DB로 재실행했다. AI는 현재 소스로 빌드한 Linux 이미지에서 네트워크를 끄고 125개 테스트를 통과했다. Windows 호스트에서 별도로 시작한 AI 테스트는 결과 없이 중단했다.
- JWT secret이 빈 Backend는 기동을 거부했다. AI 설정 로더도 내부 토큰이 비면 거부했다. Backend의 AI 클라이언트는 내부 토큰이 비어도 경고만 기록한다.

## 운영 담당 확인 사항

- 최종 배포 후 실제 image digest, 호스트·보안그룹 포트, 응답 헤더·429, SSH 키 전용 인증, IMDSv2, OS 패치, .env 권한과 운영 로그의 질문·토큰 노출 여부를 확인한다. 공급자 계정에서 운영 키 권한, 월 예산 알림과 실제 지출 차단 설정도 별도로 확인한다.

- 공식 보안점검서의 전체 완료 체크는 최종 배포 SHA의 재확인 후 갱신한다.
